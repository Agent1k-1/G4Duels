# G4Duels

Плагин дуэлей для Paper 1.21.1 и Java 21. Основной класс: `com.agent1k.g4duels.G4Duels`. Сборка через Maven.

## Возможности

- Приглашения с ограничением частоты, сроком действия, принятием и отклонением.
- Несколько арен, резервирование на весь бой, ручной или автоматический выбор свободной арены.
- Серверные киты, бой с текущим инвентарём (`own`) и бой с пустым инвентарём (`none`).
- Сохранение инвентаря, брони, второй руки, позиции, здоровья, еды, опыта, эффектов и состояния полёта перед боем.
- Восстановление после сдачи, смерти с последующим возрождением, выхода, остановки плагина и завершения по таймеру.
- Восстановление незавершённых снимков при входе после перезапуска. Файл `recovery.yml` нельзя удалять до восстановления игроков.
- Отдельные YAML-меню с пагинацией, действиями ЛКМ/ПКМ, цветами `&a`, `&#55AAFF` и `#55AAFF`.
- TabCompleter, разрешения и русские сообщения.

## Сборка и установка

```sh
mvn clean verify
```

Готовый файл: `target/G4Duels-1.0.0.jar`. Поместите его в папку `plugins` сервера Paper 1.21.1 и перезапустите сервер. Maven загружает Paper API с `repo.papermc.io`, остальные зависимости — из Maven Central. Внешние сервисы, база данных и ключи API не нужны.

В плагине нет наград, ставок, рейтинга, восстановления блоков и команд перезагрузки: эти функции не входят в задачу. Арены размещайте на отдельных подготовленных площадках с физическими границами, без доступа посторонних игроков, с отключённым появлением мобов и защитой территории средствами сервера. Плагин защищает участников и их инвентари; региональную защиту мира он не заменяет. Точки разных арен не должны пересекаться. Мир каждой арены и точки возврата должен быть загружен до включения плагина.

Изменяйте YAML при остановленном сервере. Повреждённые данные арен, китов и восстановления вызывают отказ включения вместо перезаписи файлов пустыми данными. Для изменения точек и китов во время работы используйте административные команды. Изменения записываются последовательно в отдельном потоке; ошибки записи появляются в журнале.

## Создание арен и китов

```text
/duel arena create arena1
/duel arena pos1 arena1
/duel arena pos2 arena1
/duel arena list
/duel arena delete arena1
/duel kit save classic
/duel kit list
/duel kit delete classic
```

Команды `pos1` и `pos2` сохраняют текущую позицию и направление взгляда администратора. Арена доступна после задания обеих точек в одном мире. Занятую арену нельзя удалить или изменить. Для нескольких арен повторите команды с разными именами. Имена: от 1 до 32 символов `a-z`, `0-9`, `_`, `-`.

Команда `kit save` сохраняет весь текущий инвентарь администратора, включая броню и вторую руку. Повторное сохранение с тем же именем заменяет кит. Имена `own` и `none` зарезервированы. Встроенные игровые киты не навязываются: администратор создаёт собственные.

## Команды игрока

```text
/duel <игрок>
/duel <игрок> <own|none|имя_кита> [имя_арены]
/duel accept <игрок>
/duel deny <игрок>
/duel leave
/duel restore
/duel help
```

`/duel <игрок>` открывает меню выбора кита и арены. При автоматическом выборе арена резервируется в момент принятия приглашения. У каждого отправителя может быть одно исходящее приглашение; новое заменяет предыдущее. Получатель может принять приглашение только от указанного отправителя.

Оба игрока должны быть в режиме выживания, вне транспорта и других дуэлей. Во время подготовки и отсчёта движение и урон запрещены. Во время боя запрещены передача и выбрасывание вещей, подбор предметов, открытие контейнеров, строительство и посторонние телепортации. Из команд разрешены только точные строки из `duel.allowed-commands`.

Еда разрешена. Использование остальных предметов правой кнопкой задаётся списком `duel.allowed-use-items`: по умолчанию доступны боевые предметы и надевание брони. Не добавляйте туда предметы, создающие сохраняемые сущности или изменяющие мир, без дополнительной защиты сервера. Выпущенные снаряды удаляются при завершении боя; подбор стрел запрещён. Выход и `/duel leave` засчитываются как поражение. По истечении времени объявляется ничья. Исходные предметы восстанавливаются при любом исходе.

Если другой плагин блокирует возвратную телепортацию или сохранение не удалось, состояние игрока остаётся заблокированным для защиты вещей. Устраните причину и выполните `/duel restore`. При намеренном отключении плагина устраняйте такие конфликты заранее: после отключения его обработчики защиты не работают. После аварийного завершения процесса применяется последний успешно записанный снимок; плагин не обеспечивает транзакционность между файловой системой Minecraft и собственными файлами при аппаратном сбое.

## Разрешения

| Разрешение | Назначение | По умолчанию |
| --- | --- | --- |
| `g4duels.use` | Команды игрока и дуэли | Все игроки |
| `g4duels.admin` | Управление аренами и китами | Операторы |

Алиасы: `/duels`, `/g4duels`.

## Конфигурации

| Файл | Назначение |
| --- | --- |
| `plugin.yml` | Точка входа, версия API, команды и разрешения |
| `config.yml` | Отсчёт, длительность боя, разрешённые команды и предметы, лимиты приглашений |
| `messages.yml` | Префикс, сообщения, справка |
| `arenas.yml` | Создаваемые администратором арены и точки |
| `kits.yml` | Создаваемые администратором серверные киты |
| `menus/duel.yml` | Выбор режима, арены и отправка приглашения |
| `menus/kits.yml` | Свой инвентарь, пустой инвентарь и список серверных китов |
| `menus/arenas.yml` | Автовыбор и список настроенных арен |
| `recovery.yml` | Автоматически создаваемые снимки для восстановления |

Меню загружаются в память при включении. Статические предметы находятся в `items`, динамические — в `dynamic`. Действия задаются списками `left_click_action` и `right_click_action`. Слоты нумеруются с нуля.

| Действие | Пример |
| --- | --- |
| Сообщение | `[message] &aВыбран %entry%` |
| Строка над панелью | `[actionbar] &#55AAFFДуэли` |
| Звук Bukkit | `[sound] UI_BUTTON_CLICK` |
| Открытие меню | `[menu] kits` |
| Выбор кита | `[kit] %entry%` |
| Выбор арены | `[arena] %entry%` |
| Автовыбор арены | `[arena] auto` |
| Страница | `[page] kits 1` |
| Приглашение | `[invite]` |
| Закрытие | `[close]` |

Подстановки: `%player%`, `%target%`, `%kit%`, `%arena%`, `%page%`; `%entry%` доступна у динамических предметов. Выполнение произвольных команд от консоли через меню не предусмотрено. Для изменения серверных меню нужен доступ к файлам сервера.

## Структура классов

```text
src/main/java/com/agent1k/g4duels/
├── G4Duels.java
├── action/
│   ├── Action.java
│   ├── AbstractAction.java
│   ├── MessageAction.java
│   └── ActionRegistry.java
├── arena/
│   ├── Arena.java
│   └── ArenaRepository.java
├── command/
│   └── DuelCommand.java
├── config/
│   ├── Messages.java
│   └── YamlFiles.java
├── duel/
│   ├── Duel.java
│   ├── DuelState.java
│   ├── DuelService.java
│   ├── Invitation.java
│   └── PlayerSnapshot.java
├── kit/
│   ├── Loadout.java
│   ├── BuiltinLoadout.java
│   ├── ServerLoadout.java
│   └── KitRepository.java
├── listener/
│   └── DuelListener.java
├── menu/
│   ├── MenuContext.java
│   ├── MenuHolder.java
│   └── MenuService.java
├── storage/
│   ├── AsyncFiles.java
│   └── SnapshotRepository.java
└── text/
    └── Text.java
```

`G4Duels` собирает зависимости и управляет включением и выключением. `Action` определяет контракт действия; `AbstractAction` хранит его имя, `MessageAction` использует базовый конструктор через `super`, `ActionRegistry` сопоставляет типы обработчикам без `switch`.

`Arena` хранит точки, `ArenaRepository` — арены и их резервирование. `DuelCommand` маршрутизирует команды и реализует TabCompleter. `Messages` отправляет настраиваемые сообщения, `YamlFiles` строго читает YAML.

`Duel` хранит участников, арену, состояние, задачу и снаряды. `DuelState` задаёт этапы. `DuelService` координирует приглашения и жизненный цикл боя, `Invitation` хранит приглашение, `PlayerSnapshot` захватывает и восстанавливает состояние игрока.

`Loadout` задаёт полиморфный контракт режима. `BuiltinLoadout` реализует `own` и `none`, `ServerLoadout` применяет серверный кит, `KitRepository` хранит независимые копии предметов. `DuelListener` централизует событийные ограничения и обработку смерти, входа и выхода.

`MenuContext` хранит выбор игрока внутри открытого меню, `MenuHolder` связывает инвентарь со слотами и действиями, `MenuService` строит меню и обрабатывает клики. `SnapshotRepository` хранит снимки в памяти, `AsyncFiles` последовательно записывает готовые YAML-строки через временный файл и атомарную замену. `Text` обрабатывает цвета и подстановки.

Все операции Bukkit выполняются в основном потоке. В файловый поток передаются готовые строки, а не игроки, миры или инвентари. Начало боя ожидает успешной записи снимков. Перед удалением снимка восстановленное состояние передаётся стандартному сохранению данных игрока.

## Проверки

`mvn verify` запускает 17 тестов: загрузку меню, три режима инвентаря, сдачу, смерть и возрождение, таймер, защиту от постороннего урона, запрет урона во время отсчёта, принятие приглашения только получателем, отсутствие свободной арены, запрет изменения занятой арены, права администратора, дополнение команд, порядок записи файлов, ошибочный YAML, RGB и подстановки.

Игровые интеграционные проверки выполняются в MockBukkit 4.0.0 для Paper 1.21.1. Тестовый адаптер реализует отсутствующие в этой версии MockBukkit методы создания Adventure-инвентаря, усталости и сохранения данных игрока. Проверки не заменяют испытание на отдельном настоящем сервере с боевым набором плагинов. Загрузка и игра на настоящем сервере Paper в данной среде не проверены: официальный API загрузки серверного JAR ответил `403`.
